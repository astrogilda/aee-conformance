# Git hooks

This directory is what `core.hooksPath` points at in this repository, so
every hook here is a tracked file that git actually consults. That sentence
is the whole point: for a long time the commit-message gate lived in a
directory git had been configured to ignore, and it enforced nothing.

## Set up a fresh clone

```bash
bash .githooks/install.sh
```

Once per clone. `core.hooksPath` is local config, so no clone, and no linked
worktree created before the setting existed, inherits it. The script sets one
config key, derives this directory from its own location, sets a RELATIVE
path, writes no files, and refuses to switch if any hook that runs today
would stop running. Then it proves the gate works by invoking it.

Check what git will run, at any time:

```bash
git rev-parse --git-path hooks   # never assume .git/hooks
```

## commit-msg

Refuses a commit message that breaks the documented rules:

| Rule | Rejects |
| --- | --- |
| Subject length | a subject over 72 characters |
| ASCII only | any non-ASCII byte anywhere, which is also what stops emoji and smart quotes |
| No AI attribution | `Co-Authored-By:` / `Generated with` / `Generated by` naming an assistant |
| No internal jargon | audit identifiers (`CR-9`, `HA-M5`, `AR-CRIT-1`), `DEC-YYYYMMDD-NNN`, `FAIL-YYYYMMDD-NNN`, `AR-NNN`, `AV-N`, `FUT-...`, workflow labels (`Phase 2`, `phase2`, `round-7`, `Wave B`, `Set 1.2`, `stage-0`) and session labels (`session-12`) |

Those identifiers are durable inside `DECISION_LOG.md`, `TODO.md` and code
comments, where the surrounding document resolves them. They are not durable
in a commit history that outlives the audit that minted them.

`Tier N` is deliberately NOT treated as a workflow label. Measured across the
full history of the four repositories it occurs 49 times and every occurrence
is product vocabulary (`the Tier-3 forensic dump`, `the Tier-1
static-scan-verdict predicate`), never a plan label.

Run the gate's own fixtures, or lint a range of history, without committing:

```bash
.githooks/commit-msg --selftest
.githooks/commit-msg --check-range origin/main..HEAD
```

The file is stdlib-only and imports nothing from this repository on purpose.
A hook runs before anything has been installed, so a hook that imports a
repo-local module cannot be shared with another repository -- and the two
earlier copies of this gate drifted apart for exactly that reason.

## Other hooks in this directory

None yet. This repository had no hooks and no `core.hooksPath` at all before
the commit-message gate landed here.

## commit-msg.extra-patterns (this repository only)

The gate file itself is byte-identical across the four repositories. This
repository adds one rule through the hook's extension point, in
`commit-msg.extra-patterns`: a commit message may not name the first-party
products.

That rule is real rather than decorative. This repository is public and
deliberately product-neutral, and
`.github/workflows/no-internal-drafts.yml` already refuses a tracked FILE
containing a product name -- but it greps files, and a commit message is not
a file. Three message bodies in this history name the products, which is the
same leak the file gate was built to stop, arriving through a surface nobody
checked. The other three repositories do not get this rule, where it would
forbid them from naming themselves.

## Bypass

```bash
git commit --no-verify
```

Loud and deliberate. Because that bypass exists, and because an
un-bootstrapped clone has no hook at all, `.github/workflows/commit-message-lint.yml`
runs the same tracked file over the commit messages each push and pull request
introduces.
